# Model selection protocol

Compare ordinary linear regression, Ridge, Decision Tree, Random Forest and XGBoost on exactly the same cohort, 25 raw inputs, eleven derived features, fold-local median/mode imputation, numeric scaling, one-hot encoding and chronological label purges.

Use scoring years 2016/17/18 and mean fold RMSE after clipping predictions at zero. Each tunable family receives twelve trials; ordinary least squares has one untuned benchmark configuration. Total: 49 trials and 147 fold fits. Fixed seed 42. Exact deterministic grids/samples are in `candidate_specs()` and every evaluated parameter set is saved in `tuning.json`.

Ridge explores twelve alpha values 0.01–3000. Decision Tree explores four depths × three minimum leaf sizes. Random Forest retains the six previously validated parameter sets and adds six seeded samples varying tree count, depth, leaf size and row/feature sampling. XGBoost uses twelve seeded samples varying tree count, learning rate, depth, child weight, sampling and L1/L2 regularization. Equal trial counts do not imply equal computation or exhaustive optimization.

Select family and parameters solely by the smallest unrounded mean training-fold RMSE. Ties use family then sorted parameter JSON lexical order. Record the selection before scoring 2019. Report the best training-CV specification of each family on 2019 for descriptive diagnostics; do not reverse selection from those scores. Refit only the selected specification on the purged 2014–19 cohort, save it, and score that artifact on the reused historical 2020–21 holdout. No alternative family receives a holdout score in this run.

The earlier RF-only artifact/results remain in a separate local archive, and the original research project remains unchanged. The new study does not make a universally-best-model claim: it identifies the winner among these specified searches under this evaluation design. The previously inspected holdout remains retrospective evidence. OS/library numerical differences will be reported rather than hidden.

Reference environment: Docker/Linux, matching deployment. The pre-release Windows and Linux runs selected the same forest and reproduced its reported metrics/predictions, while twelve XGBoost trials differed numerically. The Windows run is preserved and both sets of observed family results are in `platform_reproducibility.json`. Environment choice does not change the selected family, parameters or reported holdout outcome. The notebook and published tuning tables use the Docker/Linux reference; a Windows rerun may produce different nonselected-family scores. Strict full-search verification applies in the reference environment; an explicit flag reports nonselected-platform differences while keeping winner/artifact checks strict.
